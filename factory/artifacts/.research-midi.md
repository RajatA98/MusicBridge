# MIDI Library Research — React Native / Expo

**Date:** 2026-05-05
**Target stack:** Expo Development Build (not Expo Go), iOS first, Android v2, web via react-native-web.
**Goal:** Receive note-on / note-off / velocity events from a digital piano over USB MIDI and Bluetooth MIDI with low latency.

## Verification details

- **motiz88/react-native-midi** — README explicitly: "iOS support (via Core MIDI), Android support (via android.media.midi), web support". Bluetooth scanning + virtual ports listed as supported. GitHub: 78 stars, 5 open issues, last push 2023-11-25, MIT, default branch `main`. npm `@motiz88/react-native-midi@0.0.6` published 2023-11-25. Built directly on Expo Modules — installs into a dev build with `expo install`.
- **MIDIVal** — `@midival/core` is healthy (last push 2025-05-02, 121 stars), but `midival/react-native` repo last push 2022-06-08 (6 stars, npm `@midival/react-native@0.0.2` 2022-06-08). The package the user mentioned (`@midival/react-native-core-midi`) does not exist on npm; the actual package is `@midival/react-native`.
- **Expo blog (2025): "Building a MIDI-over-Bluetooth app using Expo Modules"** — Demonstrates writing a custom Expo module wrapping Core MIDI on iOS (Swift) and `android.media.midi` on Android (Kotlin). Confirms the DIY path is realistic for a small surface area (BLE scan, connect, note-on/off subscription).

## Recommendation

1. **Primary:** Use `@motiz88/react-native-midi` in the Expo dev build. It already wraps Core MIDI on iOS, `android.media.midi` on Android, and proxies to native Web MIDI on web — one JS API across all three targets, and it exposes `onmidimessage` so note-on (0x90), note-off (0x80), and velocity bytes are directly available. Pin the exact version, vendor a fork in the repo, and be prepared to patch for RN 0.74+ / new architecture if needed.

2. **Runner-up:** Layer `@midival/core` (active, well-documented high-level API: `onNoteOn`, `onNoteOff`) on top of the motiz88 package as the Web MIDI provider. This gives a nicer DX (`MIDIVal.connect().onNoteOn(...)`) without depending on the dormant `@midival/react-native` adapter. `@midival/core` consumes any Web MIDI–compatible `MIDIAccess`, which is exactly what motiz88 exposes.

3. **Fallback — build our own Expo Module (Swift/Kotlin):** If motiz88 breaks on a future RN/Expo SDK or BLE MIDI is flaky on real hardware, follow the Expo blog walkthrough and write a thin `expo-music-bridge-midi` module:
   - **iOS (Swift):** `MIDIClientCreateWithBlock`, `MIDIInputPortCreateWithProtocol`, subscribe to `MIDIEventPacket` and emit `{ status, note, velocity, timestamp }` events. For BLE, use `CABTMIDICentralViewController` or `CoreBluetooth` against the standard MIDI BLE service UUID `03B80E5A-EDE8-4B33-A751-6CE34EC4C700`.
   - **Android v2 (Kotlin):** `MidiManager` + `MidiDeviceService` for USB; `MidiManager.openBluetoothDevice` for BLE.
   - **Web:** thin wrapper over native `navigator.requestMIDIAccess()`.
   - Surface area is small (≈300 LOC per platform) because we only need device list, connect, and a note event stream.
