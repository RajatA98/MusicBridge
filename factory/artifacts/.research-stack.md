# MusicBridge Stack Research

Date: 2026-04-26
Scope: Replacement for Firebase Dynamic Links (deep links) and Claude model selection for short structured generation.

---

## 1. Deep Links (post-FDL)

### Status of Firebase Dynamic Links
Firebase Dynamic Links was deprecated in Aug 2024 and shut down on Aug 25, 2025. As of 2026, all FDL short links return 404. A direct, drop-in replacement does not exist; teams have largely consolidated around two patterns:

1. Native Universal Links / App Links backed by your own domain.
2. Third-party deep-link platforms (Branch, AppsFlyer OneLink, Adjust, HopLinks, ChottuLink).

### MusicBridge requirements recap
- Teacher generates an invite link.
- Student taps link on iOS -> opens app if installed, else web fallback that leads to App Store + signup.
- Link must carry a teacher-identifier code so signup auto-pairs.
- Must work in Expo (React Native).
- Pre-revenue, indie scale -> cost matters.

### Candidate evaluation

| Option | Setup complexity | Free tier | Deferred deep linking | Notes |
|---|---|---|---|---|
| Apple Universal Links + Android App Links + Expo Router + Firebase Hosting | Medium (one-time domain + AASA/assetlinks.json setup) | Free (you own the infra) | Partial - need a small custom mechanism (e.g. fingerprint or short-lived code via Firestore) | Best alignment with Expo Router; native, no third-party SDK. |
| Branch.io | Low (SDK install) | No free tier as of 2026; entry plan ~$499/month | First-class | Overkill for a teacher-invite flow; cost prohibitive at MusicBridge stage. |
| AppsFlyer OneLink | Medium (SDK + dashboard) | "Zero plan" with limited attribution events; full features paid | Yes | Strongest if/when you start paid acquisition; heavyweight for invite-only use case. |
| Adjust | Medium-High | No real free tier | Yes | Attribution-first; mismatch for invite use case. |
| HopLinks / ChottuLink | Low | Generous free tiers (10k+ clicks/mo on most) | Yes | Newer, smaller vendors. Lock-in and longevity risk. |
| expo-linking + custom URL scheme only | Low | Free | No (no fallback to web/store) | Insufficient on its own. |

### Recommendation: Native Universal Links + EAS/Firebase Hosting + Firestore-backed invite codes

Build the deep-link layer using Apple Universal Links (iOS) and Android App Links, served from a domain MusicBridge already controls (e.g. `musicbridge.app`). Host the `apple-app-site-association` and `assetlinks.json` files via Firebase Hosting (already in stack) or EAS Hosting.

Flow:
1. Teacher invite endpoint returns a URL like `https://musicbridge.app/invite/{inviteCode}`.
2. Firestore stores `{inviteCode -> teacherId, expiresAt, used}`.
3. iOS taps the link:
   - App installed -> Universal Link opens MusicBridge directly into the signup screen with `inviteCode` parsed by Expo Router.
   - App not installed -> Safari loads `https://musicbridge.app/invite/{inviteCode}` web page. Page persists `inviteCode` (e.g. via short-lived Firestore claim plus device fingerprint or a copy-to-clipboard prompt) and shows an "Open in App Store" button.
4. After install + first open, the app reads the pending invite code (either from clipboard with user consent or from a server lookup keyed on Apple's first-launch identifiers) and completes the pairing.

Setup complexity: Medium, one-time. Roughly:
- Configure `expo.ios.associatedDomains` and `expo.android.intentFilters` in `app.config.ts`.
- Publish AASA + assetlinks at the domain root (must be HTTPS, no redirects).
- Add an Expo Router route `app/invite/[code].tsx` that handles both web and native rendering.

Free-tier limits: Effectively unlimited. Costs are only your existing Firebase Hosting + Firestore reads (well within free Spark tier at MVP scale).

When to revisit: If MusicBridge later runs paid acquisition campaigns and needs cross-channel attribution, OneLink is the upgrade path. Branch.io should be avoided unless revenue justifies the $499/mo floor.

## 2. Claude Model Selection (Practice Checklist Generation)

### Task profile
- Input: ~50-200 words of teacher free text (~75-300 tokens).
- Assumed budget: 500 input tokens + 300 output tokens per call.
- Output: 3-7 step JSON checklist.
- Latency budget: ~5 seconds end to end inside a Firebase Cloud Function.
- Volume at MVP: low (tens to low-hundreds of calls/day).

### Pricing (per million tokens, Anthropic API, April 2026)

| Model | Input | Output | Cost per call (500 in + 300 out) |
|---|---|---|---|
| Claude Haiku 4.5 (`claude-haiku-4-5-20251001`) | $1.00 | $5.00 | $0.0005 + $0.0015 = **$0.0020** |
| Claude Sonnet 4.6 (`claude-sonnet-4-6`) | $3.00 | $15.00 | $0.0015 + $0.0045 = **$0.0060** |
| Claude Opus 4.7 (`claude-opus-4-7`) | $5.00 | $25.00 | $0.0025 + $0.0075 = **$0.0100** |

Sonnet is 3x Haiku's cost; Opus is 5x. At 1,000 calls/day:
- Haiku: ~$2/day (~$60/mo)
- Sonnet: ~$6/day (~$180/mo)
- Opus: ~$10/day (~$300/mo)

### Latency expectations

| Model | Time-to-first-token | Output speed | Estimated total for 300-token response |
|---|---|---|---|
| Haiku 4.5 | ~0.7s | ~90-120 t/s | ~3.0-4.0s |
| Sonnet 4.6 | ~1.0-1.5s | ~60-80 t/s | ~5.0-6.5s (often borderline vs 5s budget) |
| Opus 4.7 | ~1.5-2.5s | ~40-55 t/s | ~7.5-10s (over budget) |

Note: Opus 4.7 ships with a new tokenizer that can produce up to ~35% more tokens per request than 4.6, inflating both cost and latency.

### Capability fit
The task is "rewrite + structure + chunk into 3-7 steps with JSON." This is a routine structured-extraction task, well within Haiku 4.5's capability ceiling. Haiku 4.5 supports JSON mode on Anthropic and Vertex providers, which guarantees parseable output. Sonnet would only matter if assignments contained subtle musical pedagogy that required deeper inference (e.g., generating step ordering tied to skill progression). Opus is overkill.

### Recommendation: Claude Haiku 4.5

Use `claude-haiku-4-5-20251001` as the default model with:
- JSON mode enabled.
- A tight system prompt with one or two few-shot examples (cache them via prompt caching for 90% input discount).
- `max_tokens` capped around 400 to stay well inside the latency budget.
- Sonnet 4.6 as a fallback escalation if a teacher's text is unusually long (>800 input tokens) or if checklist quality regressions appear in logs.
- Do not use Opus for this path; reserve it for offline content generation or rare high-stakes summarization, not request-path Cloud Functions.

This keeps per-call cost around $0.002, p95 latency under 4s, and avoids the 5s Cloud Function timeout risk that Sonnet/Opus introduce.
